# 001: A fresh hub is proven with a real agent on a clean home

## Statement
WHEN a fresh hub is claimed proven, THE HUB SHALL have been built and opened by a real, signed-in agent in a user home that never held a hub, and the proof SHALL quote that session's own output.

## Why
A bootstrap proven only with a fake agent in a scratch folder passed every check and was never run by a stranger or on a clean machine. Proof by stand-in hides sign-in, permission and path failures that only a real agent on a real home meets (Charter II).

## How a separate agent checks it
1. Find the `proof` row in the ledger (CORE.md, Proof row). It names the agent, the model and the home it ran in.
2. Confirm the home had no hub before: a listing, dated before the build, shows no hub directory and no hub pointer. *Release only.* Per incarnation: the build ran in a shop that never held a hub (a listing dated before the build shows no hub directory and no hub pointer in it; other files may be there), and the proof row lists every instruction file the agent loaded from outside the shop.
3. Confirm the agent was real and signed in: the quoted output includes the agent's own whole footing statement (scenario 002), every line, with sign-in stated and how it was checked; not a stub's, and not an excerpt.
4. Confirm the quote is verbatim session output, with its time, and not a summary written afterwards.
Pass when all four hold.

## Falsifiability
Fails if the proof run uses a stand-in agent, reuses a home that already held a hub, or replaces the quoted output with a description.
